## Honest caveats

- The interaction-state runner is a static analysis: it parses CSS values, resolves `var()` references, and computes the WCAG ratio mathematically. It does **not** spin up a browser to verify the computed style under real conditions. This is acceptable for color contrast because the calculation is deterministic given the token hex values, but the runner cannot detect cases where the fg/bg is provided by an inline style on the element (none found in `app/globals.css`) or a child element's text color (none found in the audited selectors).
- Two overrides in the static audit result list were tagged "unresolvable" on the first run because the bg was `transparent`; I added a `--paper` fallback so the contrast check could still produce a number. This is the realistic worst case (button over the page body) and the resulting ratios (9.37 for ghost-disabled, 19.80 for stage-filter-hover) are conservative upper-bound guarantees — they pass.
- The axe-core puppeteer re-run from this session was suppressed (no Chromium binary in WSL). The 2026-08-17T10:54:18Z axe report remains the authoritative live cross-check; it is still valid because no app/* source has changed since.
