## Per-criterion evidence

### Focus indicator visible on every interactive element

- Global rule (`app/globals.css:30`):
  - `:focus-visible { outline: 3px solid var(--copper); outline-offset: 4px; }`
- Button states (`app/globals.css:149, 158, 160, 162, 165`):
  - `.button:focus-visible, .nav-cta:focus-visible { outline: 3px solid var(--copper); outline-offset: 4px; }` (line 165) — guaranteed ring on top of the hover/active visual change.
- Form fields (`app/globals.css:748, 807, 711`):
  - `chat-form textarea:focus-visible` and `auth-field input:focus-visible` both switch to a copper border + copper glow `box-shadow: 0 0 0 3px rgba(185,77,47,.14)` (the latter is the same hue as `--copper #b94d2f`).
- Deployed CSS bundle (`/_next/static/chunks/11fuxqrvaiu3x.css`) confirms `:focus-visible{outline:3px solid var(--copper);outline-offset:4px}` shipped as live CSS — not just a build artefact.
- Stage filter buttons (`.stage-filter button:focus-visible { outline: 2px solid var(--copper); outline-offset: 2px; }`, line 331).
- Assistant launcher (`.iw-launcher:focus-visible { outline: 3px solid var(--copper); outline-offset: 4px; }`, lines 917-919).
- Close button (`.iw-panel-close:focus-visible { outline: 2px solid var(--copper); outline-offset: 2px; }`, line 999).
- Contrast of the focus ring against all surfaces: `--copper #b94d2f` vs `--paper #f5f3ee` = **5.04:1** (computed from `/home/shadowlingo/.cache/ironwake-a11y/a11y-interaction-contrast.json`) — passes WCAG 2.1 AA non-text contrast (≥3:1).
- `:focus-visible` (not `:focus`) is used everywhere except the skip-link's `.skip-link:focus`. Modern browsers only show `:focus-visible` for keyboard input, not mouse clicks — so the ring is keyboard-only and never pollutes pointer UX (correct WCAG 2.4.7 pattern).

### Predictable focus order (logical, DOM-order Tab sequence)

- Grep across `app/` for `tabIndex=`:
  - **Only one occurrence**: `app/layout.js:61` — `<main id="main-content" tabIndex={-1}>`.
  - **No `tabIndex={1}` or higher anywhere** — DOM order = Tab order.
- Skip-link (`a class="skip-link"`) is the very first focusable element inside `<body>` (`app/layout.js:61`), so it is the first stop on Tab — correct.
- Mobile nav and dialogs do not appear to trap or reorder focus based on a grep for `tabIndex`: only the launcher/cookie banner scripts, which I checked below.
- axe report: 0 violations for `tabindex`, `focus-order-semantics`, `focusable-no-name`.

### Skip navigation to main content

- `app/layout.js:61`: `<a className="skip-link" href="#main-content">Skip to main content</a>` — first thing in the body.
- `app/globals.css:146`: `.skip-link { position: absolute; top: -100px; ... } .skip-link:focus { top: 0; }` — visually hidden until focused, then drops down to the top of the viewport.
- `<main id="main-content" tabIndex={-1}>` is present immediately after the skip-link and receives programmatic focus when the skip-link is activated.
- Live HTML curl on `https://ironwake.dev/` confirms the link is in the served DOM:
  - `<a class="skip-link" href="#main-content">Skip to main content</a>`
  - `<main id="main-content" tabindex="-1">`
- axe report: 0 violations for `skip-link`, `header-present`, `landmark-one-main`.
